# v0.8 English automated evaluation

v0.8 prepares two English configurations: `v0.8-core-en` (2,400 records) and
`v0.8-agentic-en` (400 records). The deterministic pilot selects 48 core and 16
agentic records, including eight intact control/stress pairs. Calibration and
public evaluation each contain 32 pilot records. These public splits are not
blind evaluations. All source records remain `draft_unreviewed`.

The release adds quality auditing, synthetic judge diagnostics, bounded study
execution, per-judge reports and evidence verification. Human review is outside
this version's scope. See [current evidence status](v0.8-results-status.md) before
interpreting any result as actual model evidence.

## Prepare and inspect

From a development checkout with the package installed, or with `PYTHONPATH=src`:

```bash
python -m humanai_impact_bench.cli prepare-v08 \
  --source data/scenarios/v0.7 --output data/scenarios/v0.8
python -m humanai_impact_bench.cli validate data/scenarios/v0.8/core/en
python -m humanai_impact_bench.cli validate data/scenarios/v0.8/agentic/en
python -m humanai_impact_bench.cli materialize-pilot \
  --dataset data/scenarios/v0.8 --track core --output .local-runs/v08-core-pilot.jsonl
python -m humanai_impact_bench.cli materialize-pilot \
  --dataset data/scenarios/v0.8 --track agentic --output .local-runs/v08-agentic-pilot.jsonl
```

Preparation is deterministic and refuses conflicting existing output. It preserves
all historical data bytes and records source hashes, changed fields, inherited
family splits and empty human-review events. New revision identifiers are not
evidence of substantive scenario improvement; content repairs need recorded audit
findings and new digests.

## Audit structure and semantic quality

```bash
python -m humanai_impact_bench.cli audit-scenarios \
  --scenarios data/scenarios/v0.8/core/en --config configs/v0.8-audit.json \
  --output .local-runs/v08-core-audit.json
python -m humanai_impact_bench.cli audit-scenarios \
  --scenarios data/scenarios/v0.8/agentic/en --config configs/v0.8-audit.json \
  --output .local-runs/v08-agentic-audit.json
```

Without `--automated`, only structural checks run; every semantic assessment is
explicitly `not_run`. The six semantic dimensions are visible grounding,
substantive escalation, distinct contexts, specific rubrics, answer leakage and
benign assistance. An empty structural findings list does not establish quality
on these semantic dimensions.

For live semantic assessment, copy the audit configuration to a local file and
set its `dataset_root`, `base_url`, `model`, optional `api_key_env`, `max_requests`
and `max_total_tokens` before adding `--automated`. The output ceiling per request
is `max_output_tokens`. `max_total_tokens` limits the sum of requested output
ceilings, including retries; it does not account for billed input tokens or dollars.
Audit execution has its own budget, separate from the study below. All paths in
the audit configuration are relative to the configuration file.

Assessments cite exact source fields/turns and may flag, abstain or fail. Model
findings are never human-review events. Changed scenarios invalidate old audit
digests and must be reassessed; unresolved findings remain visible.

## Configure a live study

`configs/v0.8-study-template.json` is deliberately non-executable. Fill every
null model/endpoint/family/digest/output-limit/budget field in a local copy; retain
null `api_key_env` only for endpoints requiring no authentication. Paths are
relative to the manifest file, so adjust them if the local copy moves directories.
Provide environment-variable names, never literal keys.

Each target needs an ID, declared family, protocol-compatible base URL, model,
candidate digest, generation temperature and positive `max_tokens`. Each judge
needs the corresponding fields except candidate digest. A hosted model alias is
not an immutable weight identifier; record the provenance limitation if only a
configuration or deployment digest is available. Family declarations are not
authenticated provider attestations.

Models can specify `api_protocol: "responses"`, `"chat_completions"`, or
`"anthropic_messages"`; omission
preserves the original Chat Completions behavior. The base URL ends at `/v1`,
and the protocol selects `/responses`, `/chat/completions`, or `/messages`. Responses requests
use `input` and `max_output_tokens`; captures retain the native provider packet.
Explicit protocol configurations require a completed answer, so token exhaustion,
empty content and unsupported output remain failed attempts rather than scores.
`timeout_seconds` is optional (default 60). Judges can explicitly set
`use_response_format: false` only after compatibility evidence shows the
structured-output option is unavailable; the choice stays bound into the manifest.
The Responses JSON-mode mapping follows the
[OpenAI structured-output API contract](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).

Anthropic Messages requests move leading system instructions into top-level
`system`, retain user/assistant history in `messages`, and use `max_tokens`.
They add the pinned `anthropic-version: 2023-06-01` header while retaining the
configured gateway's existing authentication. Only that safe version header is
captured and verified; authentication headers are never saved. Text blocks are
joined in order; thinking and redacted-thinking blocks remain in raw evidence
but are excluded from scored text. Only `stop_reason: "end_turn"` is accepted.
Tool use, missing text, token exhaustion and other stop reasons fail closed.
Custom stop sequences are not configured, so `stop_sequence` is not accepted.
See the [Anthropic Messages API contract](https://platform.claude.com/docs/en/api/messages/create).

Anthropic judges require explicit `use_response_format: false`. Their pinned
JSON instructions and strict judgment parser still apply. The adapter rejects
generic JSON mode rather than silently dropping it: Anthropic's
[structured-output contract](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
uses `output_config.format` with `type: "json_schema"`, which is not equivalent
to this runner's generic `json_object` option. The runner does not yet configure
native Anthropic JSON schemas. Verify compatibility on the configured endpoint;
a model name does not select or change the endpoint or authentication scheme.

The default matrix has two targets × two generations and two judges × two
ratings. For the 64-record pilot plus 192 synthetic diagnostic transcripts it
plans 768 target requests, 1,024 candidate-judging requests and 768 fixture-judging
requests. Two attempts per task permit at most 5,120 requests. The dry run also
computes the sum of per-request output-token ceilings; both caps must fit the
declared budget before any request is sent. This is not a dollar-cost estimate.

```bash
python -m humanai_impact_bench.cli run-study \
  --manifest .local-runs/v08-study.json --output .local-runs/v08-pilot
python -m humanai_impact_bench.cli run-study \
  --manifest .local-runs/v08-study.json --output .local-runs/v08-pilot --execute
```

The first command only validates inputs and counts requests. The second freezes
portable copies of the source, selection, fixtures and system prompt, then sends
requests. It saves raw requests and responses without authentication headers,
and records failures, retries and reserved output tokens. Rerunning resumes only
matching completed work; exhausted retries stay exhausted. A changed input,
judge prompt or runtime requires a new study directory. Use the pinned runtime
to verify an older bundle after changing code.

The 192 diagnostic transcripts are authored synthetic continuations of the 32
calibration pilot records. They cover useful responses, specific violations,
unnecessary refusal, disclaimer-only failures, formatting changes and verbosity.
Their expectations are declared hypotheses, not human gold labels. They remain
separate from candidate-generated output, and their labels are hidden from judges.

## Report and verify

```bash
python -m humanai_impact_bench.cli report-study --run-root .local-runs/v08-pilot
python -m humanai_impact_bench.cli verify-automated-evidence \
  --bundle .local-runs/v08-pilot/bundle.json
```

`report-study` writes `report.json` and `bundle.json` inside the run directory.
An alternate bundle filename must also be directly inside that directory.
Verification checks contained paths, file hashes, the planned task matrix, source
and transcript identities, actual provider responses, annotation contents and
recomputed metrics. Hashes do not authenticate a provider or prove human validity.

Results remain separate by track, split, candidate and judge. Self-judged results
are separated and declared model-family relationships remain visible. Reports
include failure-label prevalence, agreement, paired stress/control results,
synthetic contrast satisfaction and missing planned comparisons. Related records
and repeated ratings are not independent evidence. The small pilot provides
descriptive results without confidence intervals; full-corpus intervals require
the documented family support and retain family/pair structure.

Artifact integrity, execution completeness and evidence maturity are independent.
A partial run can be internally consistent while lacking comparison coverage.
All automated reports remain `PREVIEW`, with `human_review=not_performed` and
`deployment_action=HOLD`. There is no v0.8 deployment policy.

## Packaging and publication

The Hugging Face card defines only `v0.8-core-en` and `v0.8-agentic-en` for this
revision, with explicit feature types for empty nested lists. Pilot indexes and
diagnostic fixtures are not additional scenario configurations. Local loader
checks do not imply remote publication. Dataset publication, a package release,
and merging the implementation branch are separate actions.
